# Statement of Account

Per-user Statement of Account for a customer — lists every invoice (paid + outstanding) in chronological order with a running balance, plus summary totals and a 30/60/90/90+ aging breakdown of the outstanding balance. Available as JSON or as a single-page A4 PDF.

## API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/customers/<id>/statement.json[?as_of=YYYY-MM-DD]` | Get as JSON |
| GET | `/api/customers/<id>/statement.pdf[?as_of=YYYY-MM-DD]` | Download PDF |

Both share `_build_statement_payload()` internally — JSON and PDF always agree.

## JSON shape

```python
{
    "customer": {
        "id": "...", "name": "...", "contact_name": "...",
        "contact_email": "...", "address": "...", "abn": "...",
        "contact_number": "...", "gst": true
    },
    "as_of_date": "2026-09-07",
    "payment_terms": 14,
    "summary": {
        "total_invoiced": "5000.00",      # sum of total_amount across all invoices
        "total_paid": "2850.00",          # sum of amount_paid where status='paid'
        "outstanding": "2150.00",         # sum of (total - paid) where status != 'paid'
        "aging": {
            "current": "2150.00",         # not yet due
            "1_30":    "0.00",            # 1-30 days overdue
            "31_60":   "0.00",            # 31-60 days overdue
            "61_90":   "0.00",            # 61-90 days overdue
            "90_plus": "0.00"             # >90 days overdue
        }
    },
    "invoices": [
        {
            "id": "...", "invoice_number": null, "status": "paid",
            "date": "2025-12-01", "due_date": "2025-12-15",
            "description": "...",
            "total": "1500.00", "paid": "1500.00", "outstanding": "0.00",
            "age_days": null, "is_overdue": false
        },
        ...
    ]
}
```

## Aging rule

Invoices with status `sent` and `due_date < as_of_date` get rolled into the 1-30/31-60/61-90/90+ buckets based on `as_of_date - due_date`. Invoices not yet due go into `current` regardless of status. Invoices with status `draft` or `cancelled` are EXCLUDED entirely from the statement.

`age_days` is `as_of_date - due_date` for outstanding invoices, `null` for paid.

## PDF layout (single-page A4)

- Business header (top-left logo, top-right business details, ABN) —
- Bill-to block (customer name, contact, address)
- Summary tiles row: Total invoiced | Total paid | **Outstanding**
- 5-bucket aging bar (current / 1-30 / 31-60 / 61-90 / 90+)
- Invoice table with running balance column
- Bank details + payment terms footer
- Status colors: green=paid, red=overdue, orange=sent

Generated by `generate_statement_of_account_pdf()` in `app/shared/pdf.py` (ReportLab).

## Common workflows

### Generate a statement for a customer "as of today"

```python
from skills.accounts.accounting_skill import AccountingSkill
skill = AccountingSkill(api_key="...")

# As JSON (for displaying in the HMI / processing further)
data = skill.get_statement_json(customer_id="ccfa5716-...")
print(f"Outstanding: ${data['summary']['outstanding']}")
print(f"Aging 90+ : ${data['summary']['aging']['90_plus']}")

# As PDF (for emailing to the customer)
skill.download_statement_pdf(
    customer_id="ccfa5716-...",
    save_path="./customer-statement-2026-09-07.pdf",
)
```

Email the PDF just like any invoice PDF (use the local-email skill).

### Statement as of a historical date (e.g. for month-end reconciliation)

```python
# As at 30 June 2026 (end of FY2025/26)
data = skill.get_statement_json(
    customer_id="ccfa5716-...",
    as_of_date="2026-06-30",
)
# Invoices with paid_at > 2026-06-30 are treated as still outstanding
# Invoices with sent_at > 2026-06-30 are not in the statement at all
```

The `as_of_date` parameter affects:
- Which invoices are included (only those with `created_at <= as_of_date`... actually this isn't a filter — all invoices are included but the aging/status is computed "as if" as_of_date were today)
- The aging bucket boundaries (relative to as_of_date, not today)

Wait — re-read the routes.py code. The actual implementation looks at each invoice's `paid_at` vs `as_of_date` to decide if it counts as paid, and `due_date` vs `as_of_date` for aging. So as_of_date is the reference point for everything.

### Find customers with overdue invoices

```python
from skills.accounts.accounting_skill import AccountingSkill
skill = AccountingSkill(api_key="...")

customers = skill.list_customers()
overdue_customers = []
for cust in customers:
    stmt = skill.get_statement_json(customer_id=cust['id'])
    s = stmt['summary']
    if float(s['aging']['1_30']) + float(s['aging']['31_60']) + \
       float(s['aging']['61_90']) + float(s['aging']['90_plus']) > 0:
        overdue_customers.append({
            'name': cust['name'],
            'overdue': float(s['aging']['1_30']) + float(s['aging']['31_60']) +
                       float(s['aging']['61_90']) + float(s['aging']['90_plus']),
            'oldest_bucket': max(s['aging'], key=lambda k: float(s['aging'][k])),
        })
```

### Auto-attach to a reminder email

```python
import os

skill = AccountingSkill(api_key="...")

    from_addr="accounting@example.com",
    to_addrs=["accounts@example-customer.com"],
    subject=f"Statement of Account — outstanding ${outstanding}",
    body=f"Hi,\n\nPlease find your Statement of Account attached. "
         f"Total outstanding: ${outstanding}.\n\nThanks,\nEvie",
    attachments=[pdf_path],
)
```

## Things that are NOT in the statement

- **Draft invoices** — excluded. The statement only reflects what the customer has been sent or has paid.
- **Cancelled invoices** — excluded.
- **Aging of credit notes / refunds** — not modeled yet. If you issue a credit, you'd manually adjust the amount.
- **Cross-customer netting** — each customer gets their own statement. To see total receivables, sum across customers.

## Things that ARE in the statement

- All `sent` and `paid` invoices for the customer
- Total invoiced (paid + outstanding)
- Total paid (sum of amount_paid on paid invoices)
- Outstanding total + 5-bucket aging
- Per-invoice running balance
- Bank details footer (from the user/business profile)
- Payment terms (from the user/business profile, default 14 days)
